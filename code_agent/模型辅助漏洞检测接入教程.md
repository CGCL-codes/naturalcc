# NaturalCC 模型辅助漏洞检测接入教程

面向：负责“缺陷分析 / 高危预警”的前端与平台后端工程师。本文按当前仓库接口编写，示例从 `code_agent/` 根目录执行。

目标：让大模型实际阅读源码、调用扫描工具、核实告警并给出最终检测结果。先通过自带网页跑通，再接入现有平台。本文不改变原有静态扫描接口。

## 1. 先选对调用链路

| 调用方式 | 检测过程 | 大模型的作用 |
| --- | --- | --- |
| `POST /api/run`，`auto_fix=false` | 内置规则，按配置追加 Cppcheck / Clang | 不参与 |
| `POST /api/run`，`auto_fix=true` | 静态扫描后进入 Aider 修复 | 可能参与修复；不等于模型进行了检测 |
| `/api/agent/*` | 模型读取源码、选择工具、检查证据、输出结论 | 参与检测和判断 |

本教程使用第三种方式。仅在原请求里填写 `model`、API Key 或开启 `auto_fix`，不能把原来的静态扫描接口变成模型审计接口。

```text
用户选择项目、目标文件和检测类别
  → 平台后端准备 NaturalCC 服务器可访问的工作区
  → 创建 Agent Thread，保存模型配置
  → 发送审计指令，创建 Run
  → 推进 Run：模型读源码 → 调用内置扫描 → 核实告警 / 补充分析
  → 获取 Run.final_answer，校验并展示检测结果
```

本仓库负责上下文、工具、权限、执行状态和证据记录。推理由配置的模型服务提供；通过 OpenRouter 调用 Claude 等模型，不代表使用了 NaturalCC 自研模型。

## 2. 准备并启动 NaturalCC 服务

### 2.1 安装项目依赖

```bash
uv sync
uv run python scripts/install_deepseek_tokenizer.py
```

即使选用其他供应商，运行时也需要这个本地分词器来估算请求预算。它不负责漏洞检测，也不意味着请求发给了 DeepSeek。

首次使用自带网页，还需要构建前端：

```bash
cd webui
npm install
npm run build
cd ..
```

本教程的只读 Agent 扫描不启动 Cppcheck、Clang 或 Aider 子进程。需要这些扩展能力时，再按 [Pipeline 工具说明](PIPELINE_AGENT_TOOLS.md) 和 [安装说明](README.zh.md) 配置对应依赖。

### 2.2 配置模型

下面使用仓库 Contract-5 脚本采用的 OpenRouter 模型标识作为示例。实际能否调用取决于账号的模型权限、额度和供应商当前可用性。

在启动 NaturalCC 的终端中设置：

```bash
export CODE_AGENT_PROVIDER="openrouter"
export CODE_AGENT_MODEL="anthropic/claude-sonnet-4.5"
export CODE_AGENT_API_BASE="https://openrouter.ai/api/v1"
export CODE_AGENT_CONTEXT_WINDOW_TOKENS="65536"
```

通过部署环境的密钥配置向同一进程注入 `OPENROUTER_API_KEY`。这里需要 OpenRouter Key，不是 Anthropic 官方 Key。不要把真实 Key 写入前端源码、教程、提交记录或任务日志。

`65536` 是本教程的本地预算配置示例，不是对模型最大窗口的声明。应按实际模型能力配置；大文件超出可用上下文时需要拆分审计。窗口大小与后文的累计输入 Token 预算是两个不同参数。

如果接 DeepSeek 官方服务，需要同时改为 `provider=deepseek`、对应模型 ID、`https://api.deepseek.com/v1`，并配置 `DEEPSEEK_API_KEY`。本机 Ollama 的配置见 [离线部署指南](OFFLINE_PLATFORM_1_3_5.md)；不要只更换 Key 而保留旧供应商配置。

启动服务：

```bash
uv run python agent_web_api.py --host 127.0.0.1 --port 7860
```

另一个终端检查：

```bash
curl --fail http://127.0.0.1:7860/api/health
curl --fail http://127.0.0.1:7860/api/bootstrap
```

检查 Bootstrap 的 `runtime_default_model_config`，确认供应商、模型、地址和窗口符合预期。修改启动环境变量后需要重启服务。

### 2.3 确认工作区位置

`workspace` 是 **NaturalCC 服务进程所在机器上的项目绝对路径**。它不是浏览器本地路径，也不是源码上传参数。

例如，平台准备了 `/srv/tasks/task-001/project`，该目录必须能被 NaturalCC 进程实际读取。平台后端和 NaturalCC 分属两台机器时，需要共享挂载或先把项目同步到 NaturalCC 机器，再使用那里的路径；只设置远程 `NATURALCC_BASE_URL` 不会同步源码。

`target_files` 使用相对工作区的路径，例如 `src/thread.c`。它指定审计目标，不代表自动上传文件，也不禁止模型阅读工作区中的相关头文件。

## 3. 用自带网页完成一次模型审计

1. 浏览器打开 `http://127.0.0.1:7860/`。
2. 设置 **Workspace path** 为待检项目的绝对路径。
3. 将 **Runtime mode** 设为 **Agent**。
4. 点击 **New conversation**，检查当前会话的供应商和模型。
5. 在 Settings 中填写与渠道匹配的 API Key，或使用后端已配置的环境密钥。
6. 发送下一节的审计指令，把 `src/thread.c` 换成真实目标文件。
7. 查看 **Run details → Event timeline / Usage**，等待 Run 完成并取得最终回答。

旧会话保存了自己的模型配置，重启服务不会自动改掉它；首次联调建议新建会话。Settings 修改也不会改变已经创建的 Run。

本教程只做读取和审计。如果模型申请写文件、执行命令、修复或深度分析，点击拒绝，然后继续运行。不要为消除等待状态而自动批准。

## 4. 可直接复制的审计指令

下面是高危预警示例。普通平台接入可使用这份简化模板；正式复现仓库 Contract-5 评测时，使用脚本配套的 [原始提示词](artifacts/contract5/rtthread/prompt.md)，不要混用评测协议。

```text
请审计当前工作区的 src/thread.c，只检测以下四类高危问题：
buffer_overflow（缓冲区溢出）、data_race（数据竞争）、
memory_leak（内存泄漏）、command_execution（命令执行）。

先使用工作区读取工具阅读目标源码，必要时阅读同项目的相关函数和头文件。
读取时显式设置足够的 max_chars，并检查 truncated 字段；如果为 true，
说明没有读全，不得声称已完整审计。文件过大无法放入上下文时应说明覆盖限制。

阅读后调用一次 vulnerability_detection，参数为：
{"target_files":["src/thread.c"],"scan_scope":"targets","scan_type":"high_risk","severity_threshold":"low","max_findings":1000}

逐条核实工具告警。只有源码证据支持的问题才放入 findings；
不采纳的告警在 summary 中说明原因。工具没有告警也要自行检查边界、
内存所有权、同步关系和外部输入到命令执行的数据流。

仅做静态只读审计，不修改文件、不编译、不运行程序、不执行 shell，
不调用需要 execute/write 审批的工具，不调用自动修复工具。
不要读取或搜索 ground truth、测试答案、注入位置或评测标签。
每条问题给出真实函数名、1-based 源码行号、具体证据及触发条件。
不要把其他类别的缺陷强行归入上述四类。

最终只输出一个 JSON 对象，不附加解释或 Markdown 代码围栏：
{"findings":[{"category":"memory_leak","function":"实际函数名","line":实际行号整数,"reason":"证据及触发条件"}],"summary":"审计结论与覆盖限制"}
该结构仅为格式说明，不代表实际存在问题。确认没有目标问题时 findings 为 []。
```

上面的格式说明含有中文占位符，不能直接作为 JSON 数据解析；实际模型输出必须是合法 JSON。指令中的 JSON 要求是提示词约定，API 不保证模型始终遵守，接入端仍需校验。

要用于“缺陷分析”，同时修改以下两项，其余流程相同：

| 项目 | 高危预警 | 缺陷分析 |
| --- | --- | --- |
| 工具参数 `scan_type` | `high_risk` | `frequent_defects` |
| 最终允许的 `category` | `buffer_overflow`、`data_race`、`memory_leak`、`command_execution` | `array_oob`、`string_overflow`、`null_pointer` |

还应同步修改提示词中的类别解释。`scan_type` 不能代替对最终模型结果的类别校验；工具原始 findings 可能包含范围外诊断。合同 3 默认还带有教学规则开关，具体行为见 [静态分析难度调节指南](合同-3-静态分析难度调节指南.md)。

## 5. 平台后端如何调用 API

推荐由现有平台后端持有模型凭据、准备工作区并推进 Run，前端只展示平台任务与结果。原有静态扫描可继续使用 `/api/run`；新增的“模型辅助审计”任务走下面的接口。

### 5.1 创建会话

向 `POST /api/agent/threads` 发送 JSON：

```json
{
  "title": "高危预警：src/thread.c",
  "workspace": "/srv/tasks/task-001/project",
  "runtime_mode": "agent",
  "runtime_model_config": {
    "provider": "openrouter",
    "model": "anthropic/claude-sonnet-4.5",
    "base_url": "https://openrouter.ai/api/v1",
    "context_window_tokens": 65536,
    "fallback_models": []
  },
  "budget": {
    "max_llm_calls": 14,
    "max_tool_calls": 36,
    "max_input_tokens": 600000,
    "max_output_tokens": 24000,
    "max_seconds": 1800,
    "max_compaction_calls": 8
  }
}
```

响应包含 `thread_id` 和 `thread`。将 `thread_id` 保存到平台任务记录中。

这里的预算是单次审计示例上限，不是预估消费，也不保证完整扫描任意规模工程。`max_input_tokens` 是多次请求的累计预算；重复发送上下文也会累计。`max_llm_calls` 与压缩维护调用预算分别计算。

### 5.2 发送指令，创建 Run

向 `POST /api/agent/threads/{thread_id}/messages` 发送：

```json
{
  "content": "替换为第 4 节的完整审计指令，并替换目标文件名",
  "target_files": ["src/thread.c"]
}
```

响应包含 `run_id` 和 `state`。这一步创建任务，**不等于已经执行检测**。

如果 NaturalCC 进程已配置供应商密钥，可以省略 `api_key`。平台也可以在此消息请求中传 `api_key`，它不属于 `runtime_model_config`，不会写入持久化会话或 Run 快照；依赖请求密钥的任务在后端进程重启后，不能假设密钥仍在内存中。

### 5.3 推进 Run

两种驱动方式选一种，同一 Run 不要并发驱动：

| 接口 | 行为 | 使用场景 |
| --- | --- | --- |
| `POST /api/agent/runs/{run_id}/step` | 推进一步并返回当前状态，需循环调用 | 后端任务队列、逐步联调 |
| `POST /api/agent/runs/{run_id}/run` | 持续推进，直到审批、暂停或终态才返回 | 长请求驱动，同时另开连接读取事件 |

它们返回的是状态 JSON，不是原 `/api/run` 的 NDJSON。`/run` 不是立即返回的后台任务启动接口；前端、网关或代理超时不代表服务端已取消任务。

| `status` | 平台应如何处理 |
| --- | --- |
| `queued` / `running` | 继续推进，或等待已有驱动请求完成 |
| `waiting_approval` | 本教程拒绝待批工具，再继续；不能自动批准 |
| `paused` | 显示暂停，用户决定继续时调用 `/resume`，然后重新推进 |
| `completed` | 读取并校验 `final_answer` |
| `failed` / `budget_exhausted` | 展示失败或预算耗尽，并保存事件；不能按“无漏洞”展示 |
| `cancelled` | 展示已取消 |

其他控制接口均为 `POST /api/agent/runs/{run_id}` 加后缀：`/reject`、`/pause`、`/resume`、`/cancel`。只读示例的 `/reject` 不需要 JSON body。停止按钮必须调用 `/cancel`，不能只关闭浏览器连接。

创建消息响应丢失时，先查询该 Thread 的消息和 Runs，避免盲目重发导致重复任务和计费。推进请求超时后也应查询 Run 状态，确认没有其他请求仍在推进，再决定下一步。

### 5.4 获取状态和最终结果

```text
GET /api/agent/runs/{run_id}
GET /api/agent/runs/{run_id}/events?after=0
GET /api/agent/threads/{thread_id}/messages
```

状态接口直接返回状态对象。`final_answer` 是模型回答的字符串，需要解析为业务结果。事件接口返回 `{"events": [...]}`。

只对 `completed` 且输出格式校验通过的任务生成结果表；解析失败应保留原文并标记“结果格式错误”，不能用空数组替代。模型结论与工具原始告警应分别保存，避免把工具扫描结果冒充模型最终判断。

## 6. 可运行的最小 Python 接入示例

将第 4 节 `text` 代码块的内容保存为 `audit_prompt.txt`，替换其中两处目标路径。将下面代码保存为 `run_model_audit.py`。脚本只依赖 Python 标准库，通过 NaturalCC 调用模型，不直接访问供应商接口。

```python
import argparse
import json
from pathlib import Path
from urllib.error import HTTPError
from urllib.request import Request, urlopen

parser = argparse.ArgumentParser()
parser.add_argument("--base-url", default="http://127.0.0.1:7860")
parser.add_argument("--workspace", required=True, help="NaturalCC 机器上的绝对路径")
parser.add_argument("--file", required=True, help="相对工作区的目标路径")
parser.add_argument("--prompt", default="audit_prompt.txt")
parser.add_argument("--out", default="model-audit-output")
args = parser.parse_args()
base = args.base_url.rstrip("/")
out = Path(args.out)
out.mkdir(parents=True, exist_ok=False)  # 每次使用新目录，保留独立证据


def save(name, value):
    (out / name).write_text(
        json.dumps(value, ensure_ascii=False, indent=2), encoding="utf-8"
    )


def call(method, path, body=None):
    data = None if body is None else json.dumps(body).encode("utf-8")
    request = Request(base + path, data=data, method=method,
                      headers={"Content-Type": "application/json"})
    try:
        with urlopen(request, timeout=1900) as response:
            return json.load(response)
    except HTTPError as exc:
        raise RuntimeError(f"{method} {path}: HTTP {exc.code}; 请检查服务端日志") from exc


prompt = Path(args.prompt).read_text(encoding="utf-8")
config = call("GET", "/api/bootstrap")["runtime_default_model_config"]
print("模型：", config["provider"], config["model"], flush=True)
budget = {
    "max_llm_calls": 14, "max_tool_calls": 36,
    "max_input_tokens": 600000, "max_output_tokens": 24000,
    "max_seconds": 1800, "max_compaction_calls": 8,
}
thread = call("POST", "/api/agent/threads", {
    "title": f"模型审计：{args.file}", "workspace": args.workspace,
    "runtime_mode": "agent", "runtime_model_config": config, "budget": budget,
})
ids = {"thread_id": thread["thread_id"]}
save("ids.json", ids)
# 使用 NaturalCC 服务进程的环境密钥；不要把 Key 放入审计指令。
created = call("POST", f"/api/agent/threads/{ids['thread_id']}/messages", {
    "content": prompt, "target_files": [args.file],
})
ids["run_id"] = created["run_id"]
save("ids.json", ids)
run_path = f"/api/agent/runs/{ids['run_id']}"
state = created["state"]
terminal = {"completed", "failed", "cancelled", "budget_exhausted"}

while True:
    save("state.json", state)
    save("events.json", call("GET", run_path + "/events"))
    print(state["status"], "LLM calls:", state.get("llm_calls", 0), flush=True)
    if state["status"] in terminal:
        break
    if state["status"] == "paused":
        raise SystemExit("Run 已暂停；在网页检查后恢复，勿重建任务。ID 已保存。")
    action = "/reject" if state["status"] == "waiting_approval" else "/step"
    state = call("POST", run_path + action)

if state["status"] != "completed":
    raise SystemExit(f"审计未成功完成：{state['status']}；查看输出目录中的状态与事件。")

answer = state.get("final_answer", "")
(out / "final_answer.txt").write_text(answer, encoding="utf-8")
text = answer.strip()
if text.startswith("```") and text.endswith("```"):
    text = "\n".join(text.splitlines()[1:-1]).strip()
result = json.loads(text)  # 失败时保留原文，不能默认为“无漏洞”
categories = {"buffer_overflow", "data_race", "memory_leak", "command_execution"}
if not isinstance(result, dict) or not isinstance(result.get("findings"), list):
    raise ValueError("结果必须包含 findings 数组")
if not isinstance(result.get("summary"), str):
    raise ValueError("结果必须包含 summary 字符串")
for finding in result["findings"]:
    if not isinstance(finding, dict):
        raise ValueError("finding 必须为对象")
    if finding.get("category") not in categories:
        raise ValueError("出现目标范围外的类别")
    if type(finding.get("line")) is not int or finding["line"] < 1:
        raise ValueError("line 必须是正整数")
    for field in ("function", "reason"):
        if not isinstance(finding.get(field), str) or not finding[field].strip():
            raise ValueError(f"缺少有效的 {field}")
save("result.json", result)
print(json.dumps(result, ensure_ascii=False, indent=2))
```

运行示例，替换工作区和目标文件：

```bash
python run_model_audit.py \
  --workspace /srv/tasks/task-001/project \
  --file src/thread.c \
  --prompt audit_prompt.txt \
  --out audit-task-001
```

这是高危预警示例；切换缺陷分析时，还要修改脚本的 `categories` 集合。提示词文件中的目标路径必须与 `--file` 一致。正式平台应进一步核对行号不超过实际文件长度、函数和证据是否对应源码。

该脚本不自动恢复网络异常或重复提交任务。异常后用 `ids.json` 查询服务端状态，再继续已有 Run；不要直接重跑创建流程。本例的长超时用于简化联调，生产接入应由后台任务驱动，浏览器单独获取进度。

## 7. 前端进度与流式输出怎么接

最小实现可以轮询状态和事件；想显示逐步生成内容时，使用：

```text
GET /api/agent/runs/{run_id}/events.ndjson?after=0
```

这是 **NDJSON，不是 SSE**，应使用 `fetch` 读取响应流，不要直接用 `EventSource`。每个非空行是一个事件对象，主要字段为 `sequence`、`type`、`payload`。

处理约定：

- 先启动 Run 驱动，同时单独订阅事件；订阅本身不会推进 Run。
- 网络 chunk 不等于完整 JSON 行，要保留跨 chunk 缓冲，按换行分割后解析；空行是心跳。
- 保存最后处理的 `sequence`，重连时用 `after=<sequence>`，并按 sequence 去重。
- `model.content.delta` 的 `payload.text` 用于临时内容展示，按 `payload.call_index` 区分模型调用。
- `model.reasoning.delta` 可以展示 API 返回的推理文字；没有此事件不代表没有调用模型，也不能要求它提供完整内部思考。
- `tool.started` / `tool.finished` 用于工具进度；`model.usage_recorded` 用于用量信息。
- 事件流在暂停、审批和终态时可能结束，必须再查 Run 状态；流结束不能直接判定成功。
- 拒绝审批或恢复暂停后，重新驱动 Run，并从上次 sequence 重新订阅。
- 最终结果以 `completed` 状态下的 `final_answer` 为准，不能把多个调用的临时输出直接拼成最终 JSON。

接口的实际实现见 [Agent 路由](api/agent_routes.py)，现有前端消费方式见 [App.jsx](webui/src/App.jsx)。

## 8. 需要 Cppcheck / Clang 辅助时怎么办

只读 Agent 工具 `vulnerability_detection` 被适配为 `analyzer=builtin`，不会启动 Cppcheck / Clang。这种模式依然有模型参与：模型自己读取源码，结合规则证据分析并产生结论。

确需外部分析器时，让模型调用 `vulnerability_detection_analyze`。它在注册表中的规范名称为 `vulnerability_detection.analyze`，需要 `execute` 审批；指定 `analyzer=comprehensive` 时还会调用 Clang。

这属于另一种审计配置：需要安装分析器、提供编译上下文，并由用户检查后批准具体调用。本教程的只读脚本会拒绝此类请求，仓库 Contract-5 Web 评测也不会自动批准它们。不要直接删除审批边界来让任务跑通。

如果平台实现审批界面，应读取最新 Run 快照，显示待执行工具和参数，再向 `/approve` 提交对应 `risk` 和当前 `tool_call_id`；缺失或过期的 Run / 快照不能通过重建任务来绕过。详细规则见 [工具说明](PIPELINE_AGENT_TOOLS.md)。

## 9. 如何证明本次检测确实使用了模型

每次任务至少保存：

| 证据 | 用途 |
| --- | --- |
| `thread_id`、`run_id`、源码版本 / 哈希 | 对应一次可复核的审计任务 |
| `state.runtime_model_config` | 记录该 Run 选择的供应商与模型配置 |
| `model.requested`、`model.responded`、`model.usage_recorded` | 核实模型请求、成功响应与服务返回的用量 |
| 读取源码与扫描的 `tool.finished` | 检查模型实际获取的证据、读取截断与工具结果 |
| `state.final_answer` 和校验后的结果 | 保留模型最终判断及具体源码依据 |

仅有 `model.requested` 不证明请求成功；仅展示模型名称也不证明完成了审计。应结合成功响应、工具读取记录和最终结论判断。部分维护调用用于记忆检索或压缩，不能把这些调用单独当作完成漏洞审计的证据。

配置快照记录的是请求配置；若供应商发生路由，实际模型还要结合供应商用量 / 账单核实。示例设置空 fallback 列表，避免主动配置备用模型。模型是否优于静态规则需要单独评测，不能从“调用了模型”直接推出。

## 10. Contract-5 的现有评测怎么跑

先按第 2 节启动服务，确保 Bootstrap 默认配置与脚本选择的 OpenRouter 模型一致。评测脚本所在终端也需要配置 `OPENROUTER_API_KEY`，因为脚本会把它用于消息请求和额度检查。

先只查看提示词，不发模型请求：

```bash
uv run python scripts/benchmark_contract5_web.py --print-prompts
```

再跑单文件 smoke，确认模型、读取、工具和结果链路：

```bash
uv run python scripts/benchmark_contract5_web.py \
  --base-url http://127.0.0.1:7860 \
  --model anthropic/claude-sonnet-4.5 \
  --limit 1
```

检查 smoke 证据后，去掉 `--limit 1` 才是完整目标队列。脚本支持断点记录，会校验协议签名；模型、提示词或产品规则变化后，不要混入旧 checkpoint。它会写入评测产物并更新 `合同-5-result.md`，因此复测前应保留需要对比的旧报告。

正式评测保持以下边界：

- Agent 工作区仅为 `artifacts/contract5/rtthread/dataset/project/`。
- `ground_truth.json` 位于该工作区外，由评测脚本使用，不发送给模型。
- 不把 GT 当作 `ground_truth_file` 传入 Agent 工具，也不扩大授权目录让模型读取答案。
- 对模型最终预测按评测脚本的定位规则计分；静态工具的 `contract_statistics` 不能代替模型成绩。
- 单文件 smoke 只证明链路可运行；它不是完整数据集成绩，也不是合同达标结论。

本教程没有执行付费模型请求或生成新的评测成绩。仓库里的旧报告也不能证明本次平台接入已完成验收。

## 11. 常见接入问题

| 现象 | 检查与处理 |
| --- | --- |
| 填了模型但没有模型调用 | 检查是否仍在调用 `/api/run` 或选择了 Pipeline 模式 |
| 已有 Run，但一直 queued | 尚未调用 `/step` 或 `/run`；订阅事件不会启动执行 |
| 401 / 403、模型无权限、额度不足 | 检查渠道对应的 Key、模型权限与余额，不要反复重建任务 |
| tokenizer 缺失 | 执行 `uv run python scripts/install_deepseek_tokenizer.py` |
| 找不到项目 / 文件 | 检查 NaturalCC 服务器上的路径与挂载，不要使用浏览器机器路径 |
| 修改环境变量后仍使用旧模型 | 重启后端并新建会话，检查 Run 的配置快照 |
| 一直 waiting_approval | 查看待批工具；只读流程拒绝后继续，不能自动批准执行 / 写入 |
| 输入超限或 budget_exhausted | 区分单次上下文窗口与累计预算；拆分目标，按实际模型能力调整配置 |
| 没有思考面板 | 有些模型不返回推理文字，检查模型响应与用量事件 |
| 输出不是 JSON / 缺字段 | 保留原文并标记格式错误；需要时显式发起修正任务，不能按零漏洞处理 |
| 项目很大、扫描很慢 | 按文件建立审计任务，记录覆盖范围；控制并发与预算，避免一次要求审计整个工程 |
| 工具报了问题，模型没报 | 检查最终 summary 的排除理由及源码证据，分别保留两份结果 |

## 12. 接入完成后的检查项

- 浏览器页面实际创建并推进 `/api/agent/*` 的 Run。
- 模型配置、源码路径、检测类别与用户选择一致。
- 事件中有成功模型响应、目标源码读取和扫描工具执行记录。
- 模型最终结果经过结构、类别和源码位置校验。
- 失败、取消、预算耗尽、输出错误均不会显示为“未发现漏洞”。
- 页面能展示证据与模型最终判断，并保留可查询的 Run ID。
- GT 仅用于外部评估；模型审计结果与静态扫描成绩分别统计。
