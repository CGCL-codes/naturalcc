# 合同三：工程内注入教学版 v5

当前版本为 `engineering-v5-20261114`，用于学生优化检测器的教师校准实验。目标在**每工程、每套、每类**分别检查：检出率 `TP/(TP+FN) ≥85% 且 <100%`，误报率 `FP/(FP+TN)` 为 5%–15%。结果以 [总报告](合同-3-result.md) 和原始扫描 JSON 为准，不沿用旧小样例分数。

## 工程与题集

上游固定为 FreeRTOS Kernel V11.1.0、Zephyr v3.7.0、RT-Thread v5.2.1。四套 `balanced`、`independent`、`balanced-hard`、`independent-hard` 各有独立源码快照，必须成套使用源码与 GT。

```text
artifacts/contract3/engineering-v5/
  <project>-sites.json                  # 教师选点：原文件、原函数、原表达式、数组类型/容量
  <suite>/<project>/
    project/                           # 完整工程源码子集及分析头文件，学生工作区
    ground_truth.json                  # 外置教师 GT，不能交给学生扫描器
    manifest.json                      # 上游提交、原始与变更后文件哈希
  static-teaching.json                 # 学生规则实际扫描结果
  static-reference.json                # 全规则对照，如已完成测量
```

每套实际送检为 FreeRTOS 7 个完整 C 文件（约 1.66 万行）、Zephyr 124 个（约 3.19 万行）、RT-Thread 77 个（约 6.61 万行）。精确行数见 [逐套清单](合同-3-测试集与GT清单.md)，不把头文件计入 C 文件规模，也不追加无关代码凑行。

每工程每套每类有 **7 个缺陷和 7 个安全对照**，合计 42 个原有业务操作。数组操作使用真实数组的元素数；字符串操作修改原有复制/格式化长度或字符写入位置；空指针操作修改原有对象字段访问的指针来源。字符数组的类型视图来自真实声明或调用方缓冲容量前提，不能把指针的 sizeof 当数组容量。同一函数可标注多个互不重叠操作，因此统计单位是操作，不是独立函数数量。

修改仅限原有函数中的表达式；未新增独立 `contract3_*` 函数，未修改上游 checkout。安全对照只断言该操作的边界/非空前提，不宣称整个函数业务逻辑或工程其他代码无缺陷。类型视图、固定有效下标等控制版表达式是实验改动，不能作为生产补丁部署或声称保留全部运行行为。

四套是互补位置与写法的校准组合，彼此有关联；`hard` 沿用名称，不等于已证明难度排序。指标只描述冻结 GT 中的操作，不代表整个上游工程的漏洞检出率或独立泛化能力。

## 教学规则

默认仍关闭 A/B/C/E/F/G/H/I，D 开启。新增 `security_engineering_rules.py` 接入实际 `scan_c_source` 与漏洞检测插件，仅在 `scan_type=frequent_defects` 作用域运行。合同五及普通扫描不启用这些新增教学检查；缓存同时区分作用域和开关状态。

- G/C：保留“数组/字符串经指针算术访问”的漏检任务。
- E：保留指针来源的常量表达式求值任务。
- H/I：保留数组/字符缓冲最后一个合法位置的边界误报任务。
- F：保留条件表达式空分支与原有非空前提相关性判断的误报任务。

规则按 AST 形态和源码证据检查，不读取 GT、文件名/函数名白名单或目标比例，不删外部引擎的正确告警，不改计分公式。实际插件也按函数和操作行的解析/定位告警证据逐例计分，保留 `coverage_incomplete`、`total_cases`、`scored_cases`、`unscored_cases`；无关函数的语法错误不再否决已确认覆盖的操作。全规则对照只在独立测量进程中启用，不更改学生默认配置；实际参考结果也如实记录，不能预设 100%/0%。

```bash
  --suite balanced --project freertos_kernel --print-prompts --limit 1
```

Cppcheck/Clang 版本、扫描配置与默认开关共同决定本次校准范围；更换后需复测。所有标注操作需要有效函数/操作行的源解析证据或实际定位告警才能计分；不能把外部引擎退出成功等同于条件编译全覆盖。FreeRTOS 使用 POSIX 主机分析配置；Zephyr 缺少生成的板级配置；RT-Thread 使用选定主机分析配置。未启用的协程、SMP 等分支按源码审计评估，不宣称已编译执行；Clang 的部分失败及未标注告警保留在原始结果。

真实漏洞检测插件已对 balanced/FreeRTOS 做一次完整接入复测，42/42 操作计分，三类均与学生基线一致，证据为 `product-plugin-smoke.json`；这不是全部 12 组合的插件接入复测。本版未运行完整 RTOS、未完成全部业务路径的动态证明，也未进行真实 Web 模型评测。未重启已有服务或部署到甲方机器。部署时需成套更新源码、GT、分析器并在教学窗口重启后端。旧 v3 和初始 v4 工程题集及原始结果保留于各自版本目录；v4 可用 `measure_contract3_engineering.py --dataset v4` 单独复现，不能混用新版分数。
