# Contract-3 v7 多机制复核

新版路径是 `artifacts/contract3/engineering-v7/<suite>/<project>/project/`。
版本为 `engineering-v7-20261118-r4`，源码、GT 和分析证据必须使用同一版本。
本地完整矩阵 36/36 项通过：每类检出率 85%–95%、误报率 5%–15%；这是经过教学校准的结果。
用户贴出的 `contract3_balanced_hard_web_array_oob.c` 属于历史独立 fixture；v7 不生成这些文件。
v7 修改 FreeRTOS、Zephyr、RT-Thread 原有业务函数，保留完整源码文件、上游许可和 commit 来源。

每工程每套有 60 个缺陷和 60 个安全对照，三类各 20+20。每类 10 种机制，每种各 2 个正例与 2 个对照。
数组题覆盖负下标、变量传播、无符号下溢、循环结束边界、指针别名、错误守卫、有符号运算、字节/元素单位混淆等；
字符串题覆盖终止符、目标偏移、长度守卫、尾部复制、源长度误用、循环及分支长度；
空指针题覆盖初始化、覆盖赋值、错误判空、别名链、循环重置、逗号表达式、条件选择和库调用返回值。
同一套的 60 个缺陷位于 60 个不同的原业务函数，局部作用域隔离注入临时变量。

字符串 staging 题接入原格式化或拷贝操作的输入、输出和返回值；这是人为植入的业务函数改写，
不宣称是上游自然存在的漏洞。安全对照只承诺标注边界/空指针操作在 GT 所述前提下安全，
不保证改写前后的全部业务行为一致。四套共享机制与上游，不能称为独立泛化集合。

hard 套对第二个源长度复制机制，以及 RT-Thread 的第二个下标赋值机制，增加调用返回值参与计算的变体。
`strspn("", "x")` 和 `strspn("x", "y")` 的结果均为零，正例仍越界、对照仍安全；这些变体有独立 sanitizer 见证。
这是明确的教学难度校准，不应把最终比例解释为未经调校的泛化性能，也不能据此保证还会复现旧题集约 50%/90% 的引擎差距。

本次还纠正了指针比较类标注：`listIS_CONTAINED_WITHIN` 的首参只用于比较，合法 one-past 地址不能当成解引用越界。
相应正例现在形成超过 one-past 的地址；字符串直接写入的对照显式检查容量至少为 2，空指针对照显式检查原指针非空。

不能称为成功编译路径上的纯漏检率。未标注的告警不自动变成 FP。

Cppcheck 适配修复包括保留 `-imacros` 配置、将预处理错误记为失败、在不支持宏参数中的条件指令时
使用真实 Clang 预处理并保留 `#line` 定位。这里的 Clang 只负责展开源码；Cppcheck 的诊断仍由 Cppcheck 产生。
Cppcheck 分项因此注明可能依赖 Clang 预处理器，不等于启动 Clang 静态分析器。缺失真实头文件时仍明确失败。
新增工具链宏与 FTP/HTTP 功能配置是源码审计配置，不能当作完整板级构建通过的证明。
Zephyr ext2 配置采用固定版本 `subsys/fs/ext2/Kconfig` 的真实默认值 10/4096/10，分文件使用，保留来源哈希。

内置规则新增 `security_c_local_flow.py`：跟踪局部常量、赋值、别名、分支和简单计数循环，并识别实际 RTOS 链表 API 的解引用参数。
未知调用、缺少的头文件类型和未建模的循环仍有局限；新增规则不读取 GT 或 Case ID，也不改变其他合同的扫描作用域。
规则扩展前的题集和弱检出结果已保存到 `artifacts/contract3/baselines/engineering-v7-pre-flow-20261117.tar.gz`，附 SHA256；不覆盖 v6 的历史证据。

## 复现

从 `code_agent` 目录执行（不需要模型 API）：

```bash
export PATH=/mnt/onelab0/sub4-wy/luokaic/conda_envs/ncc-static/bin:$PATH
uv run --no-sync python scripts/export_contract3_ground_truth.py --verify
uv run --no-sync python scripts/verify_contract3_v7_mechanisms.py
uv run --no-sync python scripts/measure_contract3_engineering.py --timeout 600
uv run --no-sync python scripts/render_contract3_report.py
uv run --no-sync python scripts/check_contract3_teaching.py
uv run --no-sync python scripts/verify_contract3_v7_api.py --project freertos_kernel
uv run --no-sync python scripts/verify_contract3_v7_api.py --project zephyr
uv run --no-sync python scripts/verify_contract3_v7_api.py --project rt_thread
```

API 复核分别使用 JSON（展示上限 1）和表单（展示上限 100），核对正式 GT 统计相同，并与静态矩阵的同一快照一致。
测量、验收、GT 导出、报告和 Web 基准入口均默认使用 v7；复现历史工程集时显式传入 `--dataset v6`。旧版 95% 仅是历史结果。默认题集切换不重启后端服务，实际部署验收仍需针对运行中的服务单独完成。
`check_contract3_teaching.py --dataset v7` 是验收门禁，未达任一范围时返回非零；渲染报告命令只验证证据和生成报告。

## 前端直接使用

已准备好 `artifacts/contract3/engineering-v7/web-static/<suite>/<project>/`，包含与对应快照逐文件核对的源码和 `ground_truth.json`。
这是单独的静态评分副本；原始 `project/` 仍不包含教师标签。不要把外置 GT 路径 `../ground_truth.json` 传给前端，它不符合工作区路径限制。

前端选择上述目录，使用 **静态检测 / comprehensive / frequent_defects**，GT 文件填写 `ground_truth.json`，关闭自动修复。
相邻的 `<project>-request.json` 保存完整待检文件列表、600 秒分析预算与实际工作区绝对路径，避免混用旧 fixture 或全目录扫描范围。
例如 [RT-Thread balanced 的完整请求](artifacts/contract3/engineering-v7/web-static/balanced/rt_thread-request.json)。

```bash
uv run --no-sync python scripts/prepare_contract3_v7_static_workspaces.py --suite all
```

重复导出会核对已有文件，不覆盖学习者修改。引擎复现使用前面列出的 `ncc-static` 工具链 PATH；正在运行的后端没有被本次验证脚本重启或替换。
