# 合同 3：静态分析难度调节指南（出题用）

本文说明如何通过开关静态分析里的 5 处规则，调节合同 3 RTOS 测试集上"只用静态分析"的检出率，用于给学生出检测器优化题。用 [一键开关脚本](scripts/contract3_static_switches.py) 切换即可，不需要手动改代码。

> 本文包含答案（被关掉的规则就是学生要补回的内容），**不要发给学生**。

## 1. 背景与适用范围

- **测试集**：四套 RTOS 注入测试集，即 `balanced`（平衡验收集）、`independent`（独立压力集）、`balanced-hard`、`independent-hard`，由 [benchmark_contract3_independent.py](scripts/benchmark_contract3_independent.py) 生成。每套 3 类 × 20 正例 + 20 对照，共 120 个函数，按函数行范围计分。
- **5 处开关的来历**：都是针对这四套测试集的漏报分析后加入的通用规则，没有写死样例的文件名、函数名或行号。全部打开时四套检出率都是 100%；全部关掉时回到加入前的成绩。
- **只用静态分析**：内置 C 规则 + Cppcheck + Clang（即 comprehensive 模式的三个引擎），用产品的 `classify_findings` 归类，**不调用大模型**。[合同-3-result.md](合同-3-result.md) 里的 Web 成绩由大模型做最终判断，和本文的数字不会一一对应，见第 7 节。
- **误报率**：下面所有组合在四套测试集上的误报率都是 **0%**，这些开关只影响检出率。

## 2. 一键开关脚本（推荐）

脚本是 [scripts/contract3_static_switches.py](scripts/contract3_static_switches.py)，在 `code_agent/` 目录下运行：

```bash
cd /home/sub4-wy/wangchen/ncc/naturalcc/code_agent
S="uv run python scripts/contract3_static_switches.py"

$S status            # 查看 A–E 当前是开还是关
$S only A            # 只关 A，其余全开（对应第 4 节表中"只关 A"）
$S only A C E        # 只关 A、C、E，其余全开
$S off B             # 在当前状态上再关掉 B，其他不动
$S on C              # 在当前状态上重新打开 C，其他不动
$S reset             # 全部打开，恢复完整规则
$S only A --measure  # 切换后立刻测四套 RTOS 的成绩（需要 Cppcheck、Clang 在 PATH 上）
```

- `only` 是"只关这几个，其余全开"，适合直接复现第 4 节某一行；`off`/`on` 只改指定的开关，其余保持当前状态。
- 开关名不区分大小写，可以一次写多个，例如 `only a c e`。
- 每次切换后脚本会打印 A–E 的状态，并检查三个源文件仍能正常编译。
- 关闭的地方会带一行标记注释 `# [contract3-switch X off]`，用 `grep -rn "contract3-switch" *.py` 就能看到当前关了哪些。
- `reset` 会把三个文件逐字节恢复成完整规则。如果脚本提示"expected source not found"，说明这几行代码被别人改过，需要先更新脚本里的 `SWITCHES`。
- **切换后要重启 Web 后端**，正在运行的服务不会自动加载新规则。只跑第 6 节的本地测量不需要重启。

## 3. 五处开关的位置

行号会随代码修改而变化，以"搜索内容"为准。脚本做的就是下面"关闭后"这一列的替换；手动修改时也照这一列改，**不要直接把整行或整个循环注释掉**，否则 `for` 循环体会变空，导致 Python 语法错误。

| 开关 | 文件 | 搜索内容（开启时） | 关闭后 | 作用 |
|---|---|---|---|---|
| **A** | [security_contracts.py](security_contracts.py)（约第 70 行） | `string = any(call in STRING_CALLS or (call in BUFFER_CALLS and literal) for call, literal in at_line)` | `string = any(call in STRING_CALLS for call, literal in at_line)` | `memcpy`/`memmove` 的源参数是字符串字面量时，把告警归为"字符串溢出"。关闭后这类告警会被归成"缓冲区溢出"，字符串样本因此算漏报 |
| **B** | [security_analysis.py](security_analysis.py)（约第 170 行） | `if calls and any(step.get("depth", 0) > 0 ...` | 在开头加 `False and `，即 `if False and calls and any(...)` | 缺陷出现在被调用的函数内部时，Clang 告警同时在传入坏值的那一处调用上报告 |
| **C** | [security_c_rules.py](security_c_rules.py)（约第 343 行） | `results.append((node, [f"via call to {name}(): " + item for item in evidence]))` | 整行换成 `pass` | 容量规则在辅助函数里发现溢出时，在调用处报告 |
| **D** | [security_c_rules.py](security_c_rules.py)（约第 447 行） | `for node, evidence in _string_writes(function, functions):` | `for node, evidence in []:` | 容量规则本身：字符串写入的长度超过目标数组容量 |
| **E** | [security_c_rules.py](security_c_rules.py)（约第 452 行） | `for node, evidence in _null_arguments(function, functions):` | `for node, evidence in []:` | 调用同文件函数时传入 `0`/`NULL`，而被调函数没判空就解引用该参数 |

## 4. 实测效果（检出率，%）

以下数字都是实测结果，不是估算；用一键开关脚本逐行复测，结果与本表完全一致。

| 关闭的开关 | 平衡集 | 压力集 | 平衡加难 | 压力加难 |
|---|---:|---:|---:|---:|
| 无（全部开启） | 100 | 100 | 100 | 100 |
| 只关 A | 90.0 | 93.3 | 91.7 | 93.3 |
| 只关 B | 100 | 100 | 100 | 100 |
| 只关 C | 98.3 | 93.3 | 100 | 98.3 |
| 只关 D | 98.3 | 93.3 | 100 | 98.3 |
| 只关 E | 100 | 95.0 | 100 | 100 |
| 关 A + C + E | 88.3 | 81.7 | 91.7 | 91.7 |
| 关 A + D + E | 88.3 | 81.7 | 91.7 | 91.7 |
| 关 A + B + C + D + E（全关） | **86.7** | **80.0** | **91.7** | **90.0** |

几条规律：

- **A 影响最大**，四套测试集都会下降。
- **C 和 D 单独关闭效果相同**。D 是规则本身，C 是它在调用处报告的部分；在这几套测试集上，缺陷都要通过辅助函数调用才体现出来。
- **B 单独关闭没有效果**，因为它报的告警被 C/D/E 覆盖了。但在其他开关都关掉时，B 还能补回一部分：A+C+E 是 88.3 / 81.7，再关 B 和 D 才降到 86.7 / 80.0。
- **E 只影响压力集**，其他三套不变。

## 5. 推荐难度档位

| 档位 | 关闭的开关 | 一键命令 | 平衡集 / 压力集 / 平衡加难 / 压力加难 | 学生要找回的内容 |
|---|---|---|---|---|
| 很难 | A + B + C + D + E | `only A B C D E` | 86.7 / 80.0 / 91.7 / 90.0 | 5 处全部 |
| 难 | A + C + E | `only A C E` | 88.3 / 81.7 / 91.7 / 91.7 | memcpy 归类、调用处报告、NULL 实参规则 |
| 中等 | 只关 A | `only A` | 90.0 / 93.3 / 91.7 / 93.3 | memcpy 归类 |
| 简单 | 只关 E | `only E` | 100 / 95.0 / 100 / 100 | NULL 实参规则，只影响压力集 |

## 6. 改完后怎么测

只测静态分析，不调用模型、不花 API 额度，几分钟出结果：

```bash
cd /home/sub4-wy/wangchen/ncc/naturalcc/code_agent
# 本机的 Cppcheck 2.22 + Clang 18.1.8 在 conda 环境 ncc-static 中；其他机器换成自己的安装目录
# （例如 conda create -n ncc-static -c conda-forge clang=18 clang-tools=18 cppcheck）
export PATH=/mnt/onelab0/sub4-wy/luokaic/conda_envs/ncc-static/bin:$PATH
uv run python scripts/measure_contract3_static.py --suite balanced,independent,balanced-hard,independent-hard
```

- 脚本是 [scripts/measure_contract3_static.py](scripts/measure_contract3_static.py)，会输出每套测试集的检出率、误报率和各类别明细。缺少 Cppcheck 或 Clang 时会直接报错退出，不会给出不完整的分数。
- `--suite` 还支持 `juliet`、`juliet-holdout`，用于检查改动对 Juliet 第三方测试集的影响（按文件计分）。
- 全部开启时的基准结果：RTOS 四套都是 100% / 0%；Juliet 调优集 66.7% / 3.3%；Juliet 留出集 66.7% / 0%。
- 恢复全部开关：用 `uv run python scripts/contract3_static_switches.py reset`。它只撤销开关本身，不影响这三个文件里的其他改动。

## 7. 注意事项

- **对 Web 成绩的影响**：[合同-3-result.md](合同-3-result.md) 和 [合同-3-5-Web复现与手工演示.md](合同-3-5-Web复现与手工演示.md) 里的 Web 成绩由大模型做最终判断，静态分析结果只是给模型的证据，所以开关对 Web 成绩的影响是间接的。
  - C、D、E 属于内置 C 规则，Agent 默认的只读扫描工具（`vulnerability_detection`）也会用到。
  - A 和 B 只在 Cppcheck 或 Clang 运行时起作用，即 comprehensive 模式（`vulnerability_detection.analyze`）。
- **改代码后要重启后端**：Web 服务在启动时加载规则，改完不重启，新规则不会生效。
- **这是调优集上的成绩**：100% 是针对这四套测试集分析漏报后得到的，属于调优集复测，不能当作检测器的独立能力成绩。
- **不要和验收混用**：调成出题难度的代码不要用来跑验收，也不要提交到共享分支覆盖完整版规则；出题版本建议放在单独分支上。
