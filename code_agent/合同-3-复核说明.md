# 合同三：工程教学 v6 复核说明

合同数量是硬约束：**每工程每套，三类各 20 个缺陷，共 60 个缺陷；另有三类各 20 个安全对照，共 120 个标注操作。**此前 v5 降为每类 7 个缺陷，虽然比例落在区间，但违反合同数量要求，不能交付，相关结论已撤销。

当前版本为 `engineering-v6-20261114`。每类检出率目标为 ≥85% 且 <100%，误报率为 5%–15%，必须在三工程 × 四套 × 三类的 36 项结果中分别成立。数量、比例、覆盖、源码/GT/规则哈希须同时通过 `scripts/check_contract3_teaching.py`；每类少一个缺陷即失败，不允许通过缩小分母取得比例。

三工程四套已完成复测：**36/36 项均满足数量与比例要求，1,440/1,440 个操作全部计分。每类 20 个缺陷检出 19 个，检出率 95%；误报率 5%–10%。**原始逐例数据见 [总报告](合同-3-result.md) 和 `engineering-v6/static-teaching.json`，不沿用 v5 或 v3 的百分比。

FreeRTOS 内核原有字符串操作不足，扩大到官方固定版本发行工程已有的 CLI/FTP/HTTP 模块；Zephyr 扩大到同一 v3.7.0 提交的 Shell、文件系统、日志与 HTTP/DNS 模块。没有添加独立样例函数，没有重复标注同一操作来补数量。排除 sizeof/alignof 中不执行的表达式及仅出现在断言中的表达式。复制缺陷既修改实际目标地址也修改长度，确保短格式输出同样存在真实越界路径。

逐操作解析或定位告警证据决定是否可计分；未确认覆盖的位置列为 unscored，不冒充 FN/TN。部分引擎失败与原始诊断保留，不能声称完整 RTOS 编译或全部路径动态验证。教学开关 G 对全局数组直接指针形式的分类任务保持原始引擎告警，完整参考规则另行记录。
