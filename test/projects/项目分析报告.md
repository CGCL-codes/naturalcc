## 项目一：project_01_python_api — FastAPI REST API

- **测试主题**：Python FastAPI REST API 设计
- **目标**：验证 agent 是否能为 API 正确新增路由、处理 Pydantic 模型、进行异步数据库调用以及统一异常处理。

### 项目结构与功能
```
project_01_python_api/
├── main.py              # FastAPI 应用入口
├── models.py            # SQLAlchemy 数据模型（User / Item）
├── database.py          # SQLite 连接 + Session
├── routes/
│   ├── __init__.py
│   ├── users.py         # 用户 CRUD 路由
│   └── items.py         # 商品 CRUD 路由
└── requirements.txt     # 依赖清单
```

### 设计与要点
- **技术栈**：FastAPI `0.104` + SQLAlchemy `2.0` + Pydantic `2.x`，数据库采用 SQLite。
- **实体模型**：`User`（用户）与 `Item`（商品），`Item` 通过 `ForeignKey` 关联 `User`，体现数据间关系。
- **分层清晰**：入口（main）、模型（models）、连接（database）、路由（routes）职责分离。
- **API**：`main.py` 启动时 `Base.metadata.create_all` 自动建表，路由模块在入口统一挂载。
- **请求/响应模型**：分离的 `UserCreate` / `ItemCreate` BaseModel 负责入参校验。

### 可改进点
- 依赖锁定较旧（2023 年底），版本可升级；SQLite 连接可增加 `connect_args` 注释说明。
- 可补充 OpenAPI 文档 / 单元测试与错误响应统一封装。

## 项目二：project_02_js_calculator — JavaScript 计算器

- **测试主题**：JavaScript 前端交互 · 计算器应用
- **目标**：验证 DOM 操作、事件监听、四则运算逻辑（含括号、小数）、错误状态（除零、非法输入）与键盘输入处理。

### 项目结构与功能
```
project_02_js_calculator/
├── index.html             # 页面骨架
├── style.css              # 视觉样式
├── calculator.js          # 计算器核心类（Calculator）
└── tests/
```

### 设计与要点

- **双输入路径**：支持按钮点击与键盘输入统一分发。
- **错误处理**：覆盖除零、非法输入等状态。
- **可测试性**：核心方法从 DOM 解耦，便于脱离页面做单元断言。

- **目标**：验证 pandas 数据处理、matplotlib 图表生成、缺失值与异常值处理及统计分析能力。

## 项目四：project_04_cpp_algorithm — C++ 算法与数据结构

- **测试主题**：经典排序算法 + 链表数据结构
- **目标**：验证 C++ 模板/STL 运用、内存与指针管理，以及链表/栈/队列等数据结构实现。

### 项目结构与功能
```
project_04_cpp_algorithm/
├── CMakeLists.txt        # 构建配置（C++17）
├── include/
│   ├── sorting.h         # 排序算法接口声明
│   └── linked_list.h     # 单链表接口声明
├── src/
│   ├── main.cpp          # 演示入口
│   ├── sorting.cpp       # 排序算法实现
│   └── linked_list.cpp   # 链表实现
└── tests/
    └── test_main.cpp     # 单元测试（CMake 内集成）
```

### 设计与要点
- **命名空间**：`algo` 统一封装，头文件含 include guard。
- **多种排序**：冒泡、快速（Lomuto 划分）、归并（稳定 O(n log n)）、堆排（`std::make_heap`）、希尔（折半间隔）。
- **链表管理**：头插/尾插、按值删除、反转、打印；采用裸指针 + RAII 析构释放，演示内存管理。
- **构建/测试**：CMake 生成 `algorithm_demo` 与 `test_algorithm`，并注册 CTest。

### 可改进点
- 裸指针链表可考虑智能指针以增强安全性；希尔排序注释中复杂度描述可更严谨。

## 项目六：project_06_rust_cli — Rust 命令行工具

- **测试主题**：CLI 开发（Cargo + clap）
- **目标**：验证 Cargo 工程结构、clap 参数解析、文件 I/O、错误传播（anyhow）与单元测试。

### 项目结构与功能
```
project_06_rust_cli/
├── Cargo.toml            # 依赖：clap/serde/serde_json/anyhow/chrono
├── src/
│   ├── main.rs           # 入口：按子命令分发
│   ├── lib.rs            # 库入口
│   ├── cli.rs            # CLI 命令与参数定义
│   └── commands.rs       # 命令实现（greet/count_lines/format_json）
```

### 设计与要点
- **可运行子命令**：`greet`（问候）、`count`（统计行数，文件 I/O）、`json`（JSON 格式化，可选 pretty）。
- **派生解析**：clap `derive` 宏声明式定义 CLI，降低样板代码。
- **分层入口/分发**：`main` 仅做 `Cli::parse` 与匹配分发，逻辑集中在 `commands` 与 `lib`，便于库复用与测试。
- **错误传播**：全程 `anyhow::Result` 统一错误处理，`tempfile` 用于测试临时文件。

### 可改进点
- `lib.rs` 较薄，可将命令核心逻辑移动到此以提升库测试覆盖。

## 项目十：project_10_java_spring — Spring Boot 企业级应用

- **测试主题**：Spring Boot + Spring Web / Data 用户管理服务
- **目标**：验证分层工程结构、REST 控制器与服务层、异常/事务处理与数据访问层实现。

### 项目结构与功能
```
project_10_java_spring/
├── pom.xml                      # Maven 配置
└── src/main/java/com/example/demo/
    ├── DemoApplication.java              # 启动类
    ├── controller/UserController.java     # REST 控制器
    ├── service/UserService.java            # 业务服务层
    ├── repository/UserRepository.java      # 数据访问层
    ├── entity/User.java                    # JPA 实体
    ├── dto/UserCreateRequest.java          # 入参
    ├── dto/UserResponse.java               # 出参
    └── exception/
        ├── GlobalExceptionHandler.java             # 全局异常处理
        ├── ResourceNotFoundException.java
        └── UserAlreadyExistsException.java
└── src/main/resources/application.yml    # 应用配置
```

### 设计与要点
- **标准分层架构**：controller → service → repository → entity，职责清晰、易于扩展。
- **自定义 DTO**：入/出参分离，避免实体直接暴露给客户端。
- **语义化异常**：自定义 `ResourceNotFoundException` / `UserAlreadyExistsException`，配合 `@RestControllerAdvice`（GlobalExceptionHandler）统一返回错误。
- **配置外置**：`application.yml` 管理数据库与基础配置。

### 可改进点
- 不同业务/安全/事务（Spring Security、`@Transactional`）在当前轻量实现中未体现，可作为该主题的扩展方向。

## 总结与横评

| 维度 | 共性观察 |
|------|----------|
| **分层/模块化** | 各项目普遍采用清晰的目录与职责分离（如 API 分层、React 组件化、Spring 分层、链接库抽公共脚本）。 |
| **健壮性** | Python/C++/Rust/Shell 均考虑错误分支与资源清理；FastAPI 与 Spring 具备统一异常/入参校验。 |
| **可测试性** | RTC 项目多为测试主题工程：JS 计算器含单测、C++ 集成了 CMake/CTest、Rust 含 `test` 依赖，体现对验证的重视。 |
| **建衡覆盖广** | 覆盖 Web 后端、前端交互、数据处理、系统语言算法、CLI、DevOps 脚本与数据库设计，适合作为跨技术栈的 coding-agent 评测集 |

### 值得肯定的亮点
1. **工程组织规范**：无论是 Python 包结构、Cargo 模块、Java 分层还是 Shell 公共库，命名与职责规范。
2. **测试意识强**：多数项目预置了测试入口或模块解耦设计，便于自动化验证。
3. **两套 Web 后端**（FastAPI 与 Spring Boot）主题虽不同，但设计上都注意了分层、实体、DTO 与统一异常，结构完整可对比学习。

### 可选改进方向（非目标硬性要求）
- 多个项目为"轻量演示"，缺少真实依赖编排与持续集成脚本；
- 可补充类型约束（TypeScript / pydantic+静态检查）与更多单元/集成测试；
- 数据库项目可补充复杂关系图与事务演示；落地页可补全移动端菜单等 README 承诺功能。
