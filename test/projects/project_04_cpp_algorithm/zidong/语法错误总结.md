## 3. 所有 C++ 语法错误的详细清单

### 3.1 根本原因 —— `include/linked_list.h` 缺少 `#include <cstddef>`

头文件中的 `std::size_t` 拼写被缩写为 `size_t`，但该头文件内**没有包含任何提供 `size_t` 定义的标头**（如 `<cstddef>`、`<cstdint>` 等），也未在文件顶部包含使用 `size_t` 所需的头文件。

#### 错误 1：`include/linked_list.h` 第 32 行

```cpp
size_t size() const;   // 第 32 行
```

- **编译器报错**：`'size_t' does not name a type`
- **提示**：`'size_t' is defined in header '<cstddef>'`，修复方式为补加 `#include <cstddef>`。

#### 错误 2：`include/linked_list.h` 第 36 行

```cpp
size_t size_;          // 第 36 行（private 成员）
```

- **编译器报错**：`'size_t' does not name a type`
- **同根因**：同样因为缺少 `<cstddef>`。

---

### 3.2 级联产生的错误 —— `src/linked_list.cpp`

由于在 `include/linked_list.h` 中 `size_t size_;` 这一**成员字段声明失败**（见错误 2），编译器认为类 `algo::LinkedList` 并不存在名为 `size_` 的成员，于是 `linked_list.cpp` 中对 `size_` 的所有访问都会产生“未声明”错误。以下错误**并非独立的新错误，而是错误 2 的连锁反应**，修复头文件（补加 `#include <cstddef>`）即可一并消除。

| 行号 | 代码 | 编译器报错 |
|:---:|------|------|
| 10 | `LinkedList::LinkedList() : head_(nullptr), size_(0) {}` | `class 'algo::LinkedList' does not have any field named 'size_'` |
| 24 | `++size_;`（`push_front` 内） | `'size_' was not declared in this scope` |
| 36 | `++size_;`（`push_back` 内） | `'size_' was not declared in this scope` |
| 45 | `--size_;`（`remove` 内） | `'size_' was not declared in this scope` |
| 54 | `--size_;`（`remove` 内） | `'size_' was not declared in this scope` |
| 82 | `size_t LinkedList::size() const { return size_; }` | `no declaration matches 'size_t algo::LinkedList::size() const'`（因头文件中该方法声明因错误 1 而失败） |

> 说明：第 6、7、8 行的错误本质上是编译器在处理**单一编译单元**（`linked_list.cpp`）时、先解析头文件后遗留的类型/成员缺失所致，修复唯一的根因（补 `#include <cstddef>`）即可全部解决，无需改动 `linked_list.cpp` 本体。

---

## 4. 建议修复方式

在 `include/linked_list.h` 的文件头（`#ifndef` 之后、`namespace` 之前）加入：

```cpp
#include <cstddef>   // 提供 ::std::size_t
```

修复后，第 3.2 节列出的全部级联错误会自动消失。

## 5. 附加说明：CMakeLists.txt 中测试文件的引用问题（已解决）

`CMakeLists.txt` 的末尾定义了单元测试目标 `test_algorithm`，引用如下测试源文件：

```cmake
add_executable(test_algorithm tests/test_main.cpp
    src/sorting.cpp
    src/linked_list.cpp
)
```

该问题采用“方式 1”解决：

- **`tests/test_main.cpp` 缺失的问题已解决**：现已存在 `tests/test_main.cpp`（基于标准库实现、含 `main` 的无框架单元测试主程序，覆盖 `merge/heap/bubble/quick/shell` 五种排序及 `LinkedList` 的插入/删除/反转/边界情形，全部通过返回 0），`test_algorithm` 目标所需的源文件已就位。
- **同时移除了多余的 `target_link_libraries(test_algorithm PRIVATE algorithm_demo)`**：`test_algorithm` 自身已包含 `main()`，而 `algorithm_demo`（即 `src/main.cpp`）同样包含 `main()`，直接静态链接会在链接期产生重复 `main` 符号冲突，属冗余且有危害的写法，故已删除，并留下注释提示（如需共享算法实现，可将其抽成静态库 `algorithm_core` 再分别供两个可执行目标链接）。

**验证**（本环境无 `cmake`/`ctest`，改以等价 g++ 命令实测编译+链接，二者均退出码 0）：

```bash
g++ -std=c++17 -I include tests/test_main.cpp src/sorting.cpp src/linked_list.cpp -o test_algorithm.exe
g++ -std=c++17 -I include src/main.cpp src/sorting.cpp src/linked_list.cpp -o algorithm_demo.exe
```
